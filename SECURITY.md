# Security Policy

## Supported Versions

| Version  | Supported          |
| -------- | ------------------ |
| 1.0.0    | :white_check_mark: |
| <1       | :x:                |

At version 1, the project will work to provide a hardened environment.

We consider non-release versions (alpha and beta) as under development with potential issues.  While we take security issues seriously and will try to integrate discoveries for these in-development versions seriously, they do not follow our vulnerability reporting timelines.

## Reporting a Vulnerability in Released Versions

If you think you've discovered a vulnerability with the tool, then:

1. Open an issue with the title "Vulnerability in vX.Y.Z".
2. Send an email to the current project maintainer with a description, so we can start working through the issue.

While normal security practice has this start a timer for public disclosure, please keep in mind that currently this project is done through volunteer time.

## Reporting a Vulnerability for In Development Work

If you **know** for a fact this vulnerability only affects work **in development** and **does not** affect released versions, then open the security issue like any other bug.  You shouldn't start a private conversation.

## Analysis

We welcome contributions to the analysis of the security features provided by Surf Scoter.  We maintain documentation around this in the [security documentation tree](docs/security/README.md).
